# 艺账筛选交互检查（yizhang-filter-check）

## 什么时候读我

- 有人改了 index.html 里任何与「筛选」相关的代码（快捷时段、品类过滤、搜索框）。
- 需要回归验证筛选功能没有在别的改动中被弄坏。
- 以下步骤按顺序执行，不许跳步、不许凭印象下结论。

## 检查步骤

### 第 1 步：定位筛选的「骨架」

1. 在 index.html 里找到筛选控件（当前是 `.quick` 里的「今天 / 本月 / 全部」三个按钮，`data-q` 属性区分）。
2. 找到三样东西并记录行号：① 选中状态怎么标记（当前是 `class="on"`）；② 筛选值存在哪个变量；③ 列表渲染函数（`render`）在哪里读这个值。
3. 三者缺一不可——缺了任何一个，说明筛选状态没有真正接进渲染，直接记为「必须修改」。

### 第 2 步：三态行为检查（逐一核对，不许合并）

1. **有结果**：选一个确定有账的时段（如「本月」且当月有记录），列表必须且只显示该时段的账目；小计与列表一致。
2. **无结果**：选一个确定没账的时段，页面必须显示明确的空状态提示（当前是「这个时间段没有账目」类文案），不允许白屏、不允许残留上一次的数据。注意：导出按钮在无结果时应被禁用并提示，不允许导出空表。
3. **清空恢复**：切回「全部」，完整列表必须原样恢复，顺序、小计、截图缩略图都不丢。

### 第 3 步：反馈明确度检查（Day 11 原则）

1. 选中态变化要「原地可见」：被点的按钮变 `on` 样式，旧的取消——用户不用猜当前筛的是哪档。
2. 列表刷新要跟手：点了筛选按钮，列表立即变，无卡顿感。
3. 三个主题（白蓝/黑白/春天）下 `on` 选中态都清晰可辨（靠 CSS 变量，不是写死颜色）。

### 第 4 步：输出结构化结论

检查完必须按下面的格式汇报，不许只说「没问题」：

```
筛选检查结论（日期）
- 骨架：控件/状态/渲染 三者接通情况（附行号）
- 有结果：✅/❌ + 证据
- 无结果：✅/❌ + 证据
- 清空恢复：✅/❌ + 证据
- 反馈明确：✅/❌ + 证据
- 结论：通过 / 必须修改（列出具体项与建议修法）
```

## 红线

- 只检查、只报告；发现「必须修改」级问题，先报告等用户拍板，不擅自改代码。
- 本 Skill 不覆盖新增筛选功能的设计，只负责「检查已有筛选」。
